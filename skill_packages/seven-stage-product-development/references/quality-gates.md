# 단계별 품질 게이트

## Gate 1 — 요구사항 준비

- 목표 사용자와 성공 기준이 있다.
- 포함·제외 범위가 충돌하지 않는다.
- 요구사항마다 ID와 수용 기준이 있다.
- 데이터·보안·운영 환경이 누락되지 않았다.

## Gate 2 — 구현 결정 완료

- 정상·빈·오류·재시도 흐름이 정해졌다.
- 주요 인터페이스와 데이터 소유권이 정해졌다.
- 구현자가 제품 결정을 새로 내려야 하는 고영향 빈칸이 없다.

## Gate 3 — 구조·화면 검토

- 핵심 사용자 목표까지 끊긴 화면 경로가 없다.
- 필터와 상태의 적용·보존 범위가 명확하다.
- 와이어프레임이 오류·빈 상태를 포함한다.

## Gate 4 — UI 구현 준비

- 토큰과 컴포넌트 상태가 구현 가능하다.
- 대비, 키보드 포커스, 확대, 반응형 기준이 있다.
- 실제 데이터 길이와 예외 콘텐츠를 수용한다.

## Gate 5 — 코드 완료 후보

- 요구사항 추적표에 구현 위치가 연결됐다.
- 관련 단위·통합 시험이 통과했다.
- 무관한 변경·임시 코드·생성 캐시가 정리됐다.
- 실행·설치·배포 방법을 재현할 수 있다.

## Gate 6 — 출시 또는 인계

- 목표 운영 환경에서 핵심 흐름이 검증됐다.
- 알려진 결함과 미검증이 명시됐다.
- 실패·복구·롤백 절차가 위험에 비례해 준비됐다.
- 완료, 조건부 완료, 보류 중 하나로 판정했다.

## 검증 강도 선택

- 문서·카피 변경: 관련 렌더링과 링크 점검
- 로직 변경: 단위 + 통합 + 회귀
- UI 흐름 변경: 렌더링 + 키보드 + 실제 상호작용
- 데이터·스키마 변경: 마이그레이션·롤백·데이터 품질
- 인증·결제·개인정보: 권한 경계, 실패 안전성, 보안 검토
- 배포 변경: 빌드, 설치, 상태 확인, 롤백

실행하지 못한 검증은 이유와 필요한 후속 행동을 테스트 보고서에 남긴다.
